# 第 1 章　为什么是 Scoop

如果你写过 Kotlin，第一次看到 Scoop 代码时多半会觉得眼熟：`fun`、`val`、`class`、`when`、lambda、扩展函数、默认参数，写法几乎一样。但 Scoop 不运行在 JVM 上，它把程序直接编译成本机的可执行文件；它也不是“把 Kotlin 换个后端”，而是在 Kotlin 的语法基础上，重新设计了值、空值和可见性这几块基础。

本章不讲具体语法，而是先回答几个问题：

- Scoop 是一门什么样的语言，适合用来做什么；
- “编译到原生代码”“有 GC”“值类型”这几个词分别意味着什么；
- 对 Kotlin 开发者来说，哪些东西保持不变，哪些是新增的，哪些被拿掉了；
- Scoop 明确**不做**哪些事；
- 怎样使用这本书。

现在还不需要看懂每一行，只要留意几处和 Kotlin 不一样的地方：

- `struct Point(...)` 声明的是一个**值类型**：它没有对象身份，构造之后不能修改。`origin.{x: 4, y: 3}` 基于 `origin` 构造一个新值，`origin` 本身不变（第 8 章）。
- `enum Shape` 的每个分支可以携带不同的数据，相当于 Kotlin 里用 `sealed class` 写出来的一组子类，但它同样是值类型（第 9 章）。
- `when` 里的 `case Shape.Circle(_, val r)` 是**模式匹配**：判断是哪个分支，同时把里面的数据取出来。漏写分支时编译器会报错（第 11 章）。
- `Shape?` 不是“可能为 `null` 的引用”，而是 `Option<Shape>`：有值时是 `Some(shape)`，没有值时是 `None`。Scoop 没有 `null`（第 12 章）。
- 字符串插值写成 `f"area = ${area(shape)}"`，要带 `f` 前缀和花括号（第 4 章）。

除此之外，`fun`、`for`、`if`、`return`、类型标注的写法都和 Kotlin 相同。

## 1.2　一句话定位

**Scoop 是一门语法像 Kotlin、编译成原生程序、带有真正值类型的静态类型语言。**

拆开来说：

- **语法像 Kotlin**：类、接口、`object`、companion、扩展函数、lambda、默认参数和命名参数、运算符重载、`when`、异常、`suspend` 都按你熟悉的方式工作。Scoop 并不追求和 Kotlin 逐条兼容，但核心语法基本可以直接迁移。
- **编译成原生程序**：`scoop build` 产出的是一个普通的可执行文件，运行时不需要安装 JVM 或其他虚拟机。
- **真正的值类型**：除了 class，Scoop 还有 struct、enum 和 tuple 三种值类型。它们没有身份、不可修改，赋值时复制整个值，在数组里连续存放，不需要为每个元素单独分配对象。

工具链随附四十多个预编译的库，覆盖集合、文本、文件、JSON、异步 I/O、HTTP、TLS、命令行、日志、终端和桌面 GUI。所以 Scoop 适合用来写命令行工具、网络服务、桌面应用这类“需要直接交付给用户运行”的程序：你交付的是一个可执行文件，而不是一个 JAR 加一份“请先安装 Java”的说明。

## 1.3　三个词的白话解释

### 编译到原生代码

Kotlin/JVM 程序编译成字节码，运行时由 JVM 加载、解释，再由 JIT 编译器把热点代码翻译成机器码。Scoop 在**编译时**就完成了翻译：编译器（后端基于 LLVM）直接生成目标平台的机器码，链接成可执行文件。

这带来几个直接的结果：

- 程序启动快，没有虚拟机启动和预热的过程；
- 部署简单，复制可执行文件和它用到的动态库即可；
- 可以直接调用 C 函数，不需要 JNI（第 36 章）；
- 代价是要为每个目标平台分别编译。目前支持 macOS（Apple Silicon）、Linux（x86-64）和 Windows（x64）。

### 有 GC

“原生”不等于“手动管理内存”。Scoop 和 Kotlin 一样有**垃圾回收器**（GC）：class 实例在堆上分配，不再被引用的对象由 GC 自动回收，你不需要写 `free`，也不需要像 Rust 那样处理所有权和借用。

需要注意的只有一点：GC 只负责回收**内存**。文件、网络连接、锁这类资源什么时候被回收是不确定的，所以 Scoop 要求用 `use` 等方式显式关闭它们（第 21 章）。这一点和在 Kotlin 里用 `use { }` 关闭流是一样的。

> **深入一点：Scoop 的 GC**
>
> Scoop 的运行时用 C 编写，GC 采用分代的 Immix 算法：新分配的对象先放在年轻代，存活足够久的对象再晋升到老年代。值类型如果没有被装箱（见下一小节），根本不在堆上分配，也就不给 GC 增加负担。第 37 章会介绍应用开发者需要了解的内存与性能知识。

### 值类型

在 Kotlin 里，除了几个基本类型，几乎所有东西都是**引用**：变量里存的是指向堆上对象的指针，两个变量可以指向同一个对象，通过其中一个做的修改，另一个也能看到。

**值类型**的变量里存的就是数据本身。`val b = a` 把 `a` 的全部数据复制一份给 `b`，之后两者互不相干。`Int`、`Double` 一直是这样工作的；Scoop 让你自己定义的 struct、enum 和 tuple 也这样工作。

值类型带来的好处是：

- **推理简单**：值不能修改，也没有身份，不会出现“我传进去的对象被别人改了”的情况；
- **省内存、省分配**：`Array<Point>` 里的元素连续存放，不需要为每个 `Point` 分配一个对象；
- **类型安全的小包装几乎没有开销**：`struct Meters(val value: Double)` 在运行时的开销和一个 `Double` 相同，却能让编译器区分“米”和“秒”。

需要身份和可变状态的东西（用户账户、网络连接、游戏角色）仍然用 class，第 8 章会给出一张选择表。

## 1.4　对 Kotlin 开发者来说

### 基本不变的

| 方面 | 说明 |
| --- | --- |
| 声明 | `fun`、`val`/`var`、`class`、`interface`、`object`、companion、`typealias` |
| 类 | 主构造器与次构造器、`init`、单继承加接口、抽象类、`open`/`override` |
| 函数 | 表达式体、默认参数、命名参数、`vararg`、扩展函数与扩展属性、`infix`、局部函数 |
| 函数式 | lambda、匿名函数、函数类型、函数引用 `::f` |
| 控制流 | `if`/`when` 是表达式，`for`/`while`/`do-while`，区间，带标签的 `break`/`continue`/`return` |
| 其他 | 运算符重载、`try`/`catch`/`finally`、`is`/`as` 与 smart cast、`?.`/`?:`/`!!`、`suspend` |

### 新增的

| 能力 | 说明 | 章节 |
| --- | --- | --- |
| struct | 不可变的值类型，副本更新 `p.{x: 1}` | 第 8 章 |
| 带数据的 enum、tuple | 值类型的标签联合与元组 | 第 9 章 |
| 解构与模式匹配 | 嵌套解构，`when` 的 `case` 分支与穷尽性检查 | 第 10、11 章 |
| `Option<T>` | 用普通 enum 表示“可能没有值” | 第 12 章 |
| 单态化泛型 | 没有类型擦除，运行期知道真实类型 | 第 17 章 |
| 编译期能力 | 静态类型描述、自动合成编码/解码、嵌入文件 | 第 18 章 |
| 直接的 C 互操作 | `@Extern`、`Ptr`、`@CLayout` | 第 36 章 |

### 改变或拿掉的

| Kotlin | Scoop | 章节 |
| --- | --- | --- |
| `null`，`T?` 是可空引用 | 没有 `null`；`T?` 是 `Option<T>`，写 `Some(x)` / `None` | 第 12 章 |
| `data class` | `struct` | 第 8 章 |
| `enum class`、`sealed class` 表示的数据 | 带数据的 `enum` | 第 9 章 |
| `"$name"` 字符串模板 | 只有 f-string：`f"${name}"` | 第 4 章 |
| 闭包可以捕获并修改 `var` | 只能捕获 `val` | 第 7 章 |
| 数值在部分场合隐式转换 | 不同数值类型之间一律显式转换；容器下标是 `Long` | 第 3 章 |
| 默认可见性 `public` | 默认 `internal`，边界是 Cone（Scoop 的模块单位） | 第 15 章 |
| `in`/`out` 型变、`*` 投影 | 泛型一律不变 | 第 17 章 |
| `Any` 有 `equals`/`hashCode`/`toString` | `Any` 没有成员；`Equals`、`Hash`、`ToString` 要显式实现 | 第 8 章 |
| Gradle / Maven | `Cone.toml` 与 `scoop` 命令 | 第 28、29 章 |

上表里的每一项后面都有专门的章节，并配有「从 Kotlin 过来」栏，告诉你照搬 Kotlin 写法时会看到什么报错、应该怎么改。

## 1.5　Scoop 不做的事

了解一门语言**不打算**做什么，和了解它能做什么一样重要。

- **不和 JVM 互操作**。Scoop 不能调用 Java 或 Kotlin 库，也没有 `@JvmStatic`、SAM 转换、平台类型 `T!` 这类为 JVM 准备的特性。和外部世界打交道的方式是直接调用 C 函数（第 36 章）。
- **没有运行期反射**。没有 `KClass`、`::class` 的反射 API，也不能按名字查找类型、调用方法。很多原本依赖反射的需求（比如 JSON 序列化）由编译器在编译期生成代码来完成（第 18、33 章）。
- **没有 `null`**。“可能没有值”统一用 `Option` 表示，它是一个普通的 enum，编译器会要求你处理没有值的情况。
- **不在编译期保证没有数据竞争**。Scoop 不像 Rust 或 Swift 那样通过类型系统防止多个线程同时读写同一份数据。跨线程共享可变状态时，要像在 JVM 上一样显式使用原子操作、锁或 channel（第 27 章），有数据竞争的程序行为是未定义的。

## 1.6　工具一览

安装 Scoop 后，你主要和一个命令打交道：`scoop`（Windows 上叫 `sco`）。它负责格式化、检查、编译、运行、测试和生成文档：

| 命令 | 作用 |
| --- | --- |
| `scoop run` | 编译并运行程序 |
| `scoop check` | 只做语法和类型检查，不生成可执行文件 |
| `scoop fmt` | 格式化源码 |
| `scoop build` | 编译出可执行文件或库 |
| `scoop test` | 运行测试 |
| `scoop new` | 创建新项目 |
| `scoop example` | 浏览随工具链附带的离线示例 |

小程序可以只写一个 `.scoop` 文件直接运行；程序变大以后，用 **Cone** 组织：一个 Cone 就是一个带 `Cone.toml` 清单的项目目录，相当于 Gradle 里的一个模块，同时也是可见性和发布的边界（第 15、28 章）。

编辑器方面，工具链附带语言服务器 `scoop-lsp` 和 VS Code 扩展，提供诊断、补全、跳转和重命名。第 2 章会介绍安装和配置。

## 1.7　本书的阅读路线

- 先读完**第一至第三部分**。第二部分的语法大多和 Kotlin 一样，可以读得快一些，但要留意「从 Kotlin 过来」栏；第三部分是 Scoop 和 Kotlin 差别最大的地方，建议仔细读。
- 之后按需要选读：写库要看第 15 章（可见性）和第 17 章（泛型）；写网络程序要看第七部分（并发与异步）和第 34 章（HTTP）；正式开发项目要看第八部分（工程化）。
- 遇到看不懂的编译错误，查附录 B；想快速对照 Kotlin 写法，查附录 A。

## 小结

- Scoop 是语法像 Kotlin、编译成原生可执行文件、带有真正值类型的静态类型语言。
- 它有 GC，内存自动回收；文件、连接等资源仍需显式关闭。
- 值类型（struct、enum、tuple）没有身份、不可修改，赋值即复制，适合表示数据。
- 和 Kotlin 相比，最大的变化是：没有 `null`，用 `Option`；没有 `data class`，用 struct；只有 f-string 插值；闭包只能捕获 `val`；默认可见性是 `internal`；泛型不变。
- Scoop 不和 JVM 互操作，没有运行期反射，也不在编译期保证没有数据竞争。
